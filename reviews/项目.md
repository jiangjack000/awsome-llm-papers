### 为什么要做持续预训练（continuous pretraining）？
- continue pretrain是在 Pretrain 和 SFT 之间的阶段，用于在通用模型中注入领域知识。比如针对于特定的行业，金融，法律，我们自己做的是美团客服的场景，在美团APP下整个的美团客服场景比如外卖，商场，电影票，演出，还包括对于商家的销售，推广等等，综合来说就是一个客服销售交互为一体的基础模型。现在很多论文工作都说明了通用基座模型还没有达到各个尺寸模型的上限，也就是我们的模型还能学习更多知识，进行更准确的推理。但是做法却并不容易，简单的next token loss + generate 已经无法满足要求了。我们在通用基础能力的基础之上，只求提升某一方面的能力，那在某一个领域训练一个领域大模型是更加简单高效的方式。这也就是我们在做的客服大模型，在通用的基础模型基础之上，进行预训练，微调，强化学习等形成一个更强大的客服大模型。目前我们的8B的大模型已经在自己的评测榜单中超过了gpt4o和qwen2.5-72b。




### 为什么在预训练做function-call？
- 这个问题我自己在做的时候也有在思考，我觉得有两方面的原因。
- 现在的主流开源模型比如说llama，qwen都在微调时候引入function-call能力，但我觉得这也是一个问题，引入function-call能力时候过分重视指令微调而忽视了预训练过程。《The Superfical Alignment Hypothesis》认为：大模型的大部分知识是在预训练阶段获得的，在获取可泛化的基础能力方面这比微调更重要。但现在大多数的Agent侧重于指令微调以适应特定的格式或者模式，而非从根本上增强模型的知识和能力（比如API函数调用）。
- 之前之所以在微调阶段引入函数调用能力，我觉得主要原因是function-call的预训练数据稀缺。函数调用的回答和一般的指令响应不太一样，难以从现有的数据中推导中调用函数的知识。训练数据的短缺限制了大模型有效获取function-call的知识和能力
- 但微调在多个任务中的泛化能力有限。大模型代理通常难以泛化到与原始微调数据分布不同的新场景，（比如从单个工具到多个工具）。并且：SFT可以认为数据是人类偏好、任务导向的数据，相比于自然世界的语料是有偏的。需要严格确保数据质量和丰富性，防止出现hacking。
- Pretrain的数据量更大，多样性更丰富，和现实世界自然语料的分布更接近，因此不需要case by case的关注数据质量，更多的只要保证数据源的质量和可信度，并且格式也更加的自由，只需要保证模型指知道这一部分大致是干嘛的，多样性可以由其他数据源混合来提高。
- 而我在2月份恰好看到亚马逊看到的一篇论文赫菲斯托斯，这个论文提供了用于API函数调用的一个大规模预训练语料库，它包含了103B的特定代理数据，涵盖了76537个API，并且通过实验证明显著的提升了模型的FC相关的能力。而我们也有这个需求，并且我本身是做客服基座方向的，于是就有了一个初步的想法，后面也做了实验和尝试。



### 数据去重

- NUM_PERM (MinHash签名的大小)：一般常用的范围是 128 到 256。更高的值会提高签名的准确性，但同时增加计算和存储开销。
如果希望更精确地区分相似内容，可以将其设置为256或更高；128通常是一个良好的折衷选择。
- LSH_THRESHOLD (LSH的相似度阈值)：典型的值会在 0.8 到 0.95 之间。
较高的阈值（如0.9或0.95）用于非常相似的数据去重，适合内容相似度很高的文本。
较低的阈值（如0.8）可以用于希望放宽相似性标准的场景，允许更多不同但相关的内容被视为重复。
- CHUNK_LINES (每个块包含的行数)：分块行数可以根据内存和计算能力灵活设置，通常为几百到几千行（如500到1000）。
如果内存足够，较大的块可以提高处理效率，但也会增加单次内存占用和可能的延迟。

#### 原因
1. **梯度爆炸**  
   - 残差连接中梯度范数快速放大（尤其是深层网络）
   - 层间Jacobian矩阵谱范数过大导致梯度累积失控
   - 示例：Transformer层输出的梯度在反向传播时呈指数级增长

2. **优化器动态不稳定**  
   - Adam优化器的二阶动量估计偏差（如梯度方差突然变化时）
   - 参数更新量 \( \Delta \theta = -\eta \cdot \hat{m}_t / (\sqrt{\hat{v}_t} + \epsilon) \) 的剧烈波动

3. **数据分布突变**  
   - 预训练语料中突然出现高频特殊模式（如代码块、数学公式）
   - 数据分片切换时的分布不连续

#### 解决方案
#### 1. 梯度稳定性控制
| 方法                  | 实现方式                                                                 | 效果验证案例         |
|-----------------------|--------------------------------------------------------------------------|----------------------|
| **梯度裁剪**          | `torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)`      | GPT-3 训练标准配置   |
| **梯度归一化**        | 每层梯度除以该层的参数数量平方根                                         | PaLM 训练方案        |
| **混合精度优化**      | 使用 `amp.initialize()` 并设置动态 loss scaling                          | Megatron-LM 实现方案 |

#### 2. 优化器改进
```python
# 稳定版Adam实现（带二阶动量修正）
class StableAdam(torch.optim.Adam):
    def step(self):
        for group in self.param_groups:
            for p in group['params']:
                if p.grad is None:
                    continue
                grad = p.grad.data
                state = self.state[p]
                
                # 动量修正
                beta1, beta2 = group['betas']
                state['exp_avg'] = beta1 * state['exp_avg'] + (1-beta1)*grad
                state['exp_avg_sq'] = beta2 * state['exp_avg_sq'] + (1-beta2)*grad**2
                
                # 偏差修正 + 稳定性增强
                bias_correction1 = 1 - beta1 ** state['step']
                bias_correction2 = 1 - beta2 ** state['step']
                denom = (state['exp_avg_sq'].sqrt() / math.sqrt(bias_correction2)) + group['eps']
                
                step_size = group['lr'] / bias_correction1
                p.data.addcdiv_(-step_size, state['exp_avg'], denom)
```

#### 3. 模型架构优化
1. **初始化策略改进**  
   - 权重初始化标准差设为 \( \sigma = \sqrt{2/(d_{in}+d_{out})} \) [citation:7]
   - 残差分支初始化为 \( \gamma=0.1 \) 的缩放（如DeepNet的 \( \alpha \)-初始化）

2. **结构稳定性增强**
   - 在FFN层后添加额外的LayerNorm（Post-LN结构）
   - 使用RMSNorm替代LayerNorm（计算量减少30%）

#### 四、前沿研究
1. **Spectral Regularization**  
   通过对权重矩阵施加谱范数约束：  
   \( \|W\|_2 \leq c \), 其中 \( c=1/\sqrt{L} \)（L为网络深度）

2. **Gradient Surgery**  
   在优化步骤中投影梯度到稳定子空间：  
   \( g_{new} = g - \frac{g \cdot g_{prev}}{\|g_{prev}\|^2} g_{prev} \)

3. **Dynamic Loss Scaling**  
   混合精度训练中自动调整scale factor：  
   ```python
   if torch.isinf(grad).any():
       scale /= 2
       optimizer.update_scale(scale)
   elif step % 100 == 0:
       scale *= 2
   ```

### PPL
- PPL是困惑度，是交叉墒损失的指数形式。如果PPL越小，表示预测每一个Token的比率分布越确定，PPL越大，模型预测不确定性高。
- 在模型的训练过程中，PPL应该是稳步减小的。但PPL也只能自己和自己比，不同模型之间比Loss没有意义。同分词器对同一文本的 token 切割方式不同，导致概率计算基准不一致。单词表越小，则确定性越高，数值偏小。单词表越大，选择越多，数值偏大。故字符界别 < 字词级别 < 词级别

突然飙升 (>3倍)	梯度爆炸/数据分布突变	启用梯度裁剪/检查数据
